# ADR 0001: Delivery Metrics에 GitHub REST API 사용

- 상태: 승인됨
- 날짜: 2026-11-14
- 결정자: 저장소 관리자

## 문맥

대시보드는 저장소 메타데이터, 이슈, Pull Request, 커밋, 배포 정보를 수집해 변경 리드 타임과 배포 빈도 같은 delivery metrics를 보여줘야 합니다. 별도 백엔드와 데이터베이스를 운영하면 배포와 보안 구성이 복잡해집니다.

## 결정

React 프론트엔드에서 GitHub REST API를 직접 호출합니다. 공개 데이터는 인증 없이 조회하고, 선택적 `REACT_APP_GITHUB_TOKEN`은 읽기 전용 fine-grained token으로만 사용합니다. 기본 reporting window는 최근 30일이며, 화면에서 새로고침할 수 있습니다.

## 대안

- **GitHub GraphQL API:** 여러 리소스를 한 번에 조회할 수 있지만 쿼리 복잡도와 오류 처리가 증가합니다.
- **별도 백엔드 수집기:** 토큰을 서버에 안전하게 보관할 수 있지만 운영 인프라와 저장소가 추가됩니다.
- **GitHub Actions만 사용:** 정기 집계에는 적합하지만 실시간 새로고침과 대화형 탐색이 제한됩니다.

## 결과

- 별도 서버 없이 GitHub Pages에 배포할 수 있습니다.
- 공개 저장소는 빠르게 확인할 수 있습니다.
- 브라우저에 전달되는 토큰은 비밀로 취급할 수 없으므로 권한을 최소화해야 합니다.
- API rate limit과 페이지네이션 제한을 사용자에게 로딩·오류 상태로 안내해야 합니다.
